# HH: проверка результата больше не ломает ручную страницу

> История, 16 октября 2026: владелец отменил HH-доступ через Tailscale.
> Более новый результат: [капча через Telegram](2026-10-16-hh-telegram-captcha.md).
> Описанная здесь web-схема выведена из эксплуатации.

16 октября 2026. Продолжение приёмки
[мобильного ручного режима](2026-10-16-hh-mobile-manual-release.md).

На iPhone удалось открыть страницу после проверки настроек DNS. Пользователь
увидел капчу, ввёл текст и нажал «Готово», но доступ не подтвердился. На сервере
ручной режим остался active; на видимой странице HH оказалась незагруженная
картинка. Успешное прохождение настоящей капчи этим не подтверждено.

Причина дефекта: read-only проверка повторно открывала исходный адрес в самой
ручной вкладке. HH перенаправлял её на капчу, а необходимый странице POST
инициализации был правильно запрещён во время checking. После неуспеха
пользователь возвращался к сломанной странице без объяснения.

Теперь проверка использует временную вкладку того же Chromium/profile. Она
разрешает только чтение, проверяет точный исходный адрес штатным reader и
закрывается в finally. Ручная вкладка с картинкой и введённым текстом остаётся
на месте. При неуспехе сохраняются active, исходный incident и claims; сбор
не возобновляется, answer/init POST не повторяются.

Мобильный интерфейс после неуспешного «Готово» объясняет, что HH не подтвердил
доступ, и предлагает верхнюю кнопку «Обновить проверку». Старый экран не
подключается автоматически. Подсказка поясняет, что нижнее поле является
удалённой клавиатурой: символы сразу передаются в HH, после чего поле очищается.
Свежую картинку нужно получать верхней кнопкой, а не стрелкой внутри HH.

## Проверки и установка

- Gateway suite: 13/13, включая мобильный touch/Unicode/failed finish.
- Linux Chromium: 1/1, включая сохранение картинки, текста, URL и числа вкладок
  при неуспехе; отсутствие новых init/answer POST во время проверки.
- Настоящий Linux noVNC/Xvfb/headed Chromium: 1/1, включая отсутствие автоматического
  возврата к старому экрану и явное обновление перед повторным подключением.
- Coordinator/broker на Windows: шесть passed и один Linux-only skip;
  их production-код в этом исправлении не менялся.

Browser и gateway установлены на DE из immutable release
`e93e7f467bbbc18f3e802a33e231a42bfffd442e`; их код и public assets сверены с
принятыми файлами. Профиль HH и окружение сохранены. Collector остановлен
на время замены browser и запущен с тем же container ID. Остальные сервисы
не пересоздавались. После замены gateway локальный proxy переподключён к его
актуальному адресу. Оба source checkout синхронизированы с GitHub main.

На самом iPhone остаётся повторно открыть страницу, получить свежую картинку,
ввести ответ, нажать «Отправить» в HH и «Готово» сверху. Реальный успех и
возобновление сбора в этом исправлении ещё не подтверждены. Новые ответы
на капчу и отклики за владельца при диагностике не отправлялись.
