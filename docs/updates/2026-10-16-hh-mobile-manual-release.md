# Ручная капча HH с телефона: выпуск на DE

16 октября 2026. Владелец поручил публикацию и установку в этом чате.
[Проект](../superpowers/specs/2026-10-16-hh-mobile-manual-design.md) и
[стендовые проверки](2026-10-16-hh-mobile-manual-development.md) сохранены отдельно.

## Что установлено

В GitHub main опубликована реализация; Windows и оба VPS получили одинаковые
исходники. На DE server, collector, browser и новый gateway установлены из
immutable release `895e4ebcb7c4185c5b411db603ee00e1962a6b91`. Последующие изменения
касаются host proxy и документов; входные файлы контейнеров совпадают с main.
На NL обновлены исходники; поиск работы там не запускался. Desktop 1.0.2
соответствует принятому коду и не требовал переустановки.

Постоянный адрес `/hh/` доступен через HTTPS 443 Tailscale Serve. Прежний
маршрут `/` на HTTPS 10000 сохранён без изменений. Funnel выключен.
Кнопка «Открыть HH» включена доверенной настройкой меню и уведомлений владельца.
Адрес не содержит токена и не имеет таймера. Ссылка открывает страницу;
ручное управление начинается только после явного действия владельца.

Docker 29.6.0 на этом VPS не создал фактический published port у контейнера
с единственной internal network. Поэтому установлен штатный host socket proxy
на `127.0.0.1:19123`. Gateway остался в прежней изолированной сети. Launcher
проверяет фиксированный контейнер/сеть, сбрасывает root, группы и capabilities,
затем запускает системный `systemd-socket-proxyd`. Его процесс работает как
UID 65534 без permitted/effective/ambient capabilities. При активации адрес
контейнера определяется заново; ошибка запуска не меняет manual state.
Схема установки и обновления описана в [deploy README](../../deploy/README.md).

HH profile, выбранное резюме, настройки и mounted secret inodes сохранены.
Проверены owner в PostgreSQL и совпадение его scope между сервисами. В Tailscale
подтверждены действующая учётная запись и зарегистрированный в ней iOS peer.
Личные идентификаторы, login, адреса профиля и секреты в отчёт не включены.

## Фактические проверки

- Все четыре обновлённых сервиса запущены; server/browser/gateway healthy.
  Их исходники внутри контейнеров совпадают с опубликованными файлами.
- Прежние PostgreSQL, OCR, ASR и Cloudflare container IDs не изменились.
  Host Agent и VPN-службы DE/NL остались активными.
- С компьютера владельца через настоящий Tailscale HTTPS загружаются страница,
  status и noVNC assets. Serve передаёт нужную identity и сохраняет `/hh/`.
- Прямой запрос без identity и с чужим login получает 403. Это проверка шлюза;
  реальный вход с другой Tailscale учётной записью отдельно не выполнялся.
- Неверный CSRF отвергается без изменения состояния. Открытие ссылки не
  запускает ручную проверку. Raw VNC слушает только container loopback;
  IPv6 VNC, X TCP и CDP listeners отсутствуют.
- Очередной штатный collector tick встретил CAPTCHA и создал pending.
  Настройки не изменились; сохранены 51 оставшийся запрос и страница 16.
  Повторные проверки ждут владельца, не отправляя ответ на CAPTCHA.
- Три проверки host proxy проходят на Windows и Linux; systemd units проходят
  проверку конфигурации. Полные server/Telegram и Chromium/noVNC результаты
  перед выпуском перечислены в development record.

## Что ещё не подтверждено

На самом iPhone ещё нужно включить Tailscale, открыть постоянную ссылку,
начать ручную проверку, увидеть экран, ввести ответ и нажать «Готово».
Успешное прохождение настоящей CAPTCHA и возобновление сбора в этом выпуске
пока не подтверждены. Автоматические и стендовые проверки не заменяют этот шаг.
Новые отклики от имени владельца во время выпуска не отправлялись.
