# Установка обработки капчи HH и результат настоящей попытки

15 октября 2026. Владелец поручил публикацию и обновление VPS. Код
`4e515e5dd7cb625b636c0354c86ddba3eb9e23ca` опубликован в GitHub `main`,
получен Windows и обоими VPS. На DE установлен отдельный release
`/home/deploy/releases/jarvis-4e515e5-hh-captcha`.

## Что установлено и проверено

- Пересобраны server, job-collector, job-browser и новый job-ocr. Worker стал
  healthy до включения `JARVIS_HH_CAPTCHA_RECOVERY=1` в браузере. Миграция
  `031_job_captcha_attention.sql` применена обычным startup-путём сервера.
- Сохранены прежний HH profile volume, выбранное резюме, остальные переменные
  окружения и inode смонтированных секретов с правами 0600. У других контейнеров
  проекта ID не изменились. NL получил только исходники; VPN не переустанавливался.
- В готовых образах прошли 23 серверные проверки, 7 браузерных и 3 OCR-проверки.
  Полные проверки разработки перечислены в [предыдущей записи](2026-10-15-hh-captcha-recovery-development.md).
- Файлы работающих server/collector/browser совпали с release: 286/286/24
  исходных файла. Для OCR отдельно совпали worker, health, manifest, alphabet
  и requirements; установлены закреплённые версии шести Python-пакетов.
- Worker работает без сети и host ports, с read-only rootfs, одним socket
  volume и лимитом памяти 512 MiB. Browser монтирует socket volume read-only.
- Все четыре компонента работают, server/browser/OCR healthy. Public live/ready
  smoke прошёл. Release-status не обнаружил расхождений Windows/GitHub/DE/NL,
  server build inputs, Host Agent и установленного Desktop 1.0.2. Desktop не менялся.

## Настоящая попытка не восстановила сбор

До обновления поиск был остановлен на `JOB_HH_CAPTCHA_REQUIRED`: 328 отправленных
карточек, очередь пустая, checkpoint ещё отсутствовал. Сохранённый progress:
52 поисковых окна, страница 34, смещение 16 первого окна. Вакансии не были исчерпаны.

Для проверки после установки только ближайший `next_check_at` перенесён на текущее
время с проверкой owner, отсутствия lease, включённого поиска и прежней причины
остановки. Фильтры, период и progress не менялись.

В 21:30:41 МСК browser сохранил incident `waiting`, collector назначил повтор
на 21:32:41. Повтор запустился в 21:32:46 и завершился в 21:33:00 кодом
`JOB_HH_CAPTCHA_MANUAL_REQUIRED`; journal перешёл в `blocked`. Telegram attention
создано и отправлено один раз. Новых карточек нет: осталось 328, progress прежний,
lease освобождён. Следующая штатная проверка назначена на 22:02:46 МСК.

Это подтверждает запуск отложенной попытки и уведомления, но не успешное
прохождение капчи. Сохранённого закрытого результата недостаточно, чтобы
приписать отказ конкретно распознаванию, форме или принятию ответа HH.
Контейнеры не перезапускались аварийно и не были остановлены OOM. Единственный
OCR request-failure в логах был до попытки, поэтому не доказывает её причину.

Journal не сбрасывался; повторная отправка ответа для этого incident запрещена.
Нужно вручную восстановить доступ в прежней HH-сессии на DE и затем проверить
продвижение progress и новые Telegram-карточки. Публичный доступ к браузеру не
открывался. Отклики на вакансии не отправлялись.

## Ограничение приёмки

Установка завершена; автоматическое прохождение настоящей капчи и возобновление
сбора не подтверждены. Успех OCR на одном предыдущем образце не гарантирует
успех на других. [Контракт и ограничения OCR](../../job-ocr/README.md).
