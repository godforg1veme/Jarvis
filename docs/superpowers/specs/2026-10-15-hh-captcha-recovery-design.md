# Ограниченная бесплатная обработка капчи HH

15 октября 2026. Владелец поручил автоматическую попытку, бесплатный вариант,
проверку на вредоносное ПО и последующую реализацию. Выбор реализации уточнён
после чтения реальной формы и изолированных проверок качества.

## Проверенные основания

В сохранённой сессии HH показана графическая капча с двумя русскими словами.
Форма: POST `https://hh.ru/account/captcha`, query `backurl,state`, поля
`_xsrf,captchaText,isBot`. Изображение появляется после пустого POST
`https://hh.ru/captcha?lang=…`; затем GET `/captcha/picture?key=…`.
Ответ капчи пока не отправлялся. Изображения и значения формы не входят в Git.

ddddocr 1.6.1 исключён: встроенные алфавиты не поддерживают полный русский язык.
Tesseract rus не распознал образец в 24 вариантах. EasyOCR cyrillic gen2
приблизился к визуальной расшифровке, но точного совпадения не дал.
Официальная `PaddlePaddle/cyrillic_PP-OCRv5_mobile_rec_onnx` после полярного
выпрямления дала точное совпадение в 19 вариантах, серия заняла около секунды.
Это один образец, не измерение точности на независимой выборке и не live proof HH.

## Компоненты

1. `job-ocr`: Python 3.12/Linux amd64, CPU ONNX Runtime, Pillow/numpy.
   Закреплённые wheels/hashes и официальный ONNX snapshot. Никакого LLM,
   стороннего solver API, произвольного кода моделей или загрузки runtime-моделей.
   UNIX HTTP socket `/run/job-ocr/ocr.sock`, UID 1001, directory 0700/socket 0600.
   Сеть отсутствует, rootfs read-only, cap_drop ALL, no-new-privileges,
   512 MB RAM, 1 CPU, 64 PID, временный tmpfs. Единственный общий volume — socket.
2. Browser читает только закрытую форму HH и обрезанное PNG-изображение.
   Worker получает до 256 KiB PNG, максимум 2048×512 и 1 048 576 пикселей.
   Ответ — ровно `{answer:string}`: два русских слова длиной 2–20 букв,
   разделённые одним пробелом. Никаких путей, URL, команд или инструкций.
   Несколько вариантов геометрии должны согласиться; иначе отказ.
3. Browser хранит owner-bound журнал фазы/operation ID/времени/hash исходного
   URL в приватном профиле. Первая капча создаёт waiting до now+120 секунд.
   Фазы initializing и attempted синхронизируются на диск **до** соответствующих POST.
   Initializing/attempted/blocked после перезапуска не разрешают повторную отправку.
   Только GET исходной страницы может подтвердить восстановление доступа.
4. Collector получает закрытые CAPTCHA_WAITING/MANUAL_REQUIRED коды,
   назначает короткий повтор по waiting и сохраняет обычный progress/checkpoint.
   Неудача ставит deduplicated attention в существующую owner-scoped очередь.
   Telegram показывает фиксированное уведомление без OCR, исключений и токенов.

## Разрешённые изменения HH

Автоматика действует только для поиска и чтения вакансий при явном opt-in.
Один пустой POST `/captcha?lang=<разрешённый язык>` допустим только из main frame
проверенной страницы `/account/captcha`, привязанной backurl к запрошенной странице.
Ответ отправляется не более одного раза, в тот же exact form action и main frame,
с точным OCR answer и исходными hidden-полями. `isBot` и `_xsrf` не подменяются.
Другие поля, дубликаты, произвольный redirect, внешняя форма и другой POST запрещены.
Это расширяет read credential только для этой капчи; отправка откликов по-прежнему
требует отдельного apply credential и подтверждённого письма.

После неудачи, неизвестного результата, неподдержанного widget или недоступности
OCR — уведомление и никаких автоматических повторов POST. Следующие плановые
чтения могут обнаружить ручное восстановление доступа. Существующий blacklist,
видимость резюме, фильтры и бюджет модели не меняются.

## Проверки и выпуск

Нужны отрицательные protocol/ownership/restart/injection/limit тесты, настоящее
Chromium прохождение синтетической формы с подсчётом всех записей, реальная
PostgreSQL очередь и уведомление с чужим scope, регрессии browser/server/Telegram.
Картинки капчи, ответы, tokens и приватные журналы не сохраняются в репозитории.
Флаг по умолчанию выключен. Доступный локальный результат готовится до предложения
выпуска; GitHub/VPS публикация требует отдельного поручения по release-workflow.
