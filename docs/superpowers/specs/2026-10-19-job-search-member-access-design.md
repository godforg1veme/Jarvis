# Поиск работы для участников и личное подключение HH

**Статус:** проект одобрен владельцем 19 октября 2026. Исходный код реализуется локально в `codex/jobs-member-hh`; релиз и acceptance ещё не выполнены.

## Цель

Участник с действующим разрешением `jobs` должен подключить собственный аккаунт
HH и пользоваться поиском вакансий в своём Telegram-чате. Вход должен быть
понятным и доступным с телефона и ПК через обычный HTTPS, без Tailscale и
установки дополнительных программ. Профиль владельца HH не используется для
участников.

## Причина

RBAC уже позволяет выдать роль с разрешением `jobs`, и Telegram показывает
участнику кнопку поиска. Дальше путь всё ещё ограничен ролью `owner`: ранний
ответ находится в `TelegramMenuService`, а `JobTelegramService`, проверки
области, репозитории, фоновые задания, доставка и browser RPC повторно требуют
главного владельца. Browser runtime хранит один постоянный профиль с одним
HH-аккаунтом. Участник поэтому получает сообщение о личном подключении, но
завершить такое подключение или начать поиск не может.

## Пользовательский сценарий

1. Участник открывает настроенный Mini App Jarvis в Telegram на телефоне или
   Telegram Desktop и выбирает «Поиск работы».
2. В разделе отображаются статус подключения и действие «Подключить HH».
   Jarvis создаёт короткоживущую одноразовую сессию входа. Mini App показывает
   кнопку открытия сессии и короткую ссылку с системным share/copy для перехода
   на другом устройстве. Отдельный QR-код сейчас не создаётся.
   Capability не отправляется сообщением в Telegram. В ссылке он передаётся в
   URL fragment, который не отправляется HTTP-серверу автоматически; после
   обмена на сессию клиент очищает fragment.
3. Сессия открывает адаптивную страницу обычного HTTPS-домена Jarvis. На ней
   отображается ограниченный снимок удалённой страницы HH в отдельном браузерном
   профиле участника. Пользователь нажимает поле HH, вводит текст через
   клавиатурную строку страницы Jarvis и отправляет его в активное поле. По
   умолчанию ввод скрыт; его можно временно показать для проверки почты или кода.
   Значения кратко присутствуют в памяти вкладки и проходят по HTTPS через
   server gateway и browser RPC. Они не сохраняются в БД, файлы, Telegram,
   логи или diagnostics. Показ входа доступен только на время подключения;
   владелец инфраструктуры технически управляет серверным браузером.
4. После входа Jarvis проверяет, что HH сессия активна, и получает ограниченный
   список собственных резюме. Сессия Mini App, создавшая вход, показывает
   найденный профиль и список резюме. Если резюме одно, оно предлагается
   выбранным; если несколько, участник должен явно выбрать основное. Подтверждение
   проходит в исходной сессии Mini App. Никакое резюме владельца не подставляется.
5. Jarvis показывает «HH подключён». Временная возможность управлять страницей
   закрывается; поисковый раздел начинает использовать только личный профиль
   участника. Отклик работодателю по-прежнему требует отдельного подтверждения
   точного текста в том же Telegram-чате.

Если тот же участник открывает ссылку на другом устройстве, короткий срок и
user-bound session сохраняют область подключения. Повторное получение того же
ещё действующего ticket возвращает ту же browser session для восстановления после
потерянного HTTP-ответа. Участник может открыть Mini App на любом устройстве,
где доступен его Telegram; перенос ссылки — запасной сценарий.

## Доступ по ролям

- Главный владелец определяется сервером по числовому Telegram ID и остаётся
  единственным владельцем общей VPN/Operations инфраструктуры. Сохранённое
  `users.role='owner'` не подтверждает владельца и не заменяет эту проверку.
- Участник с `jobs` получает поиск только для своей записи membership и своего
  Telegram ID. Администратор по умолчанию имеет все секционные разрешения,
  но его HH профиль также отдельный и его уровень не открывает чужие данные.
- Текущие `allow/deny` и блокировка продолжают действовать. Права проверяются
  по свежему состоянию при запуске входа, каждом действии, guided input и
  callback, а также перед фоновым поиском, обработкой CAPTCHA и отправкой.
- Область Telegram остаётся частной: conversation, chat и user ID должны
  принадлежать одному и тому же участнику. Чужой или групповой чат не может
  создать или использовать сессию.
- Отзыв `jobs`, блокировка или смена ревизии membership аннулирует ожидающий
  capability, завершает удалённое управление и запрещает новые/фоновые
  действия. Уже подключённый профиль можно снова использовать после повторной
  выдачи права; его данные не удаляются автоматически.

Общие правила ролей не меняются. «Ассистент», Life OS, память, документы и
устройства остаются привязаны к данным участника; VPN и системные Operations
сохраняют owner-bound границы.

## Архитектура и границы доверия

- Mini App создаёт capability только для аутентифицированной Telegram-сессии с
  текущим разрешением `jobs`. В базе хранится хеш capability, user ID,
  membership revision, закрытый статус и срок действия. Исходный bearer token
  показывается только внутри клиентской сессии, передаётся во fragment URL и
  после обмена очищается. Он не попадает в URL query, Telegram-сообщения,
  диагностику или логи.
- Capability привязан только к созданию/управлению одной HH login-сессией, имеет
  короткий TTL и не является Mini App сессией или общим API credential. Повтор
  того же действующего ticket идемпотентно открывает ту же сессию, но не создаёт
  вторую. Просроченный, чужой или отозванный ticket завершается отказом.
  Публичные страницы используют существующий HTTPS origin и серверные
  Origin/CSRF-проверки.
- Browser runtime остаётся во внутренней Compose-сети без публичного host port,
  Tailscale или Docker socket. Существующий серверный HTTPS endpoint выступает
  единственной точкой входа. Браузер принимает только закрытые операции из
  server gateway и открывает только необходимые страницы HH и проверенные
  страницы входа HH.
- Публичный server gateway передаёт только изображение страницы и ограниченные
  события ввода активной connection-сессии. Он не становится общим прокси или
  произвольным удалённым браузером. Для перехода по ссылке на другом устройстве
  исходная Mini App сессия подтверждает аккаунт и выбранное резюме до завершения
  привязки.
- Для каждого внутреннего user UUID выделяется отдельный приватный профиль
  Chromium и отдельное состояние восстановления CAPTCHA/откликов. Права
  каталогов остаются 0700, файлы — 0600. Ошибка разрешения пути, symlink,
  несовпадение user binding или доступ к чужому профилю закрывает действие.
  Очередь/параллелизм ограничены ресурсами одного VPS.
- Постоянный HH профиль и cookies хранятся на Jarvis VPS в отдельном volume,
  как текущий профиль владельца. Экран подключения заранее объясняет это. Пароль,
  одноразовый код и значения полей кратко проходят через HTTPS в памяти, но не
  сохраняются в БД, файлах, долговременном application state, Telegram или логах.
  Страница держит временный буфер для восстановления после потерянного ответа и
  очищает его после подтверждения ввода либо закрытия вкладки. Сервис может
  обслужить удалённую браузерную сессию; владелец инфраструктуры технически
  контролирует серверный профиль.
- PostgreSQL содержит только связь user UUID, статус подключения и ID/название
  выбранного резюме. Пароли, cookies, HTML, снимки экрана и тексты HH не
  сохраняются в таблицах, квитанциях и диагностике.
- Исходная отдельная apply credential сохраняет назначение и границы. Любая
  подготовка/отправка остаётся user-bound и требует прежнего подтверждения
  точного текста, резюме и вакансии; неизвестный результат не повторяется.
- Не добавлять production-зависимости без отдельного согласования. Если текущего
  HTTP/browser runtime недостаточно для понятного и отзывчивого входа, сначала
  представить владельцу конкретный вариант и его ограничения.

## Состояния и ошибки

Подключение имеет закрытые фазы `created`, `active`, `verified`, `expired`,
`revoked` и `failed`; произвольные сообщения HH и значения формы не являются
диагностическими значениями. Публичный клиент получает короткие сообщения:
ссылка истекла, требуется повторный вход, HH недоступен, доступ отозван или
нужно выбрать резюме. При ошибке входа и истечении TTL управление браузером
закрывается. Неподтверждённый новый профиль удаляется, чтобы не оставлять
случайно созданную частичную сессию. Уже подтверждённый профиль не удаляется
автоматически при временном отказе или отзыве роли.

Если результат соединения неизвестен, клиент сверяет исходный ticket/session
ID; повторный запрос с новым ID не создаёт ещё одну браузерную сессию. Повторное
нажатие на уже подключённый профиль показывает его безопасный статус, не начинает
новый вход.

## UI и контракт

Существующая нижняя Telegram-клавиатура, надпись «Поиск работы» и callback
грамматика сохраняются. Меняется результат для разрешённого участника:
он входит в личный job-раздел, а при отключённом HH получает путь к разделу
подключения Mini App вместо повторяющейся заглушки о браузере владельца.
Mini App добавляет простое состояние подключения и временного входа; новых
категорий guided input в Telegram не требуется. Уведомления остаются только
участнику, которому принадлежит профиль.

## Вне объёма

- Передача или повторное использование HH cookies/профиля главного владельца.
- Сбор HH пароля в форме Jarvis, его отправка через Telegram, хранение в БД,
  конфигурации, истории, логе или диагностике.
- Прямой публичный порт браузера/CDP, установка VPN-клиента пользователям,
  автоматическая регистрация/вход на HH, обход CAPTCHA или ограничений HH.
- Чтение или изменение данных другого пользователя, массовая миграция профилей
  либо удаление действующего профиля владельца.
- Изменение доступов VPN, Operations, устройств, памяти, документов, Life OS
  или общего поведения ролей.

## Приёмка

- Участник с ролью только `jobs` может из личного Telegram начать вход через
  Mini App на телефоне и обычном ПК без установленного Tailscale.
- Два тестовых пользователя и владелец получают разные HH профили, резюме,
  поиски, историю, CAPTCHA состояния и доставки. Ни один cross-user запрос не
  получает результат другого профиля.
- Выдача, отзыв, deny override и блокировка действуют при открытой login-сессии,
  в уже созданном callback/guided input и в фоне.
- Повтор, истечение срока, чужой Telegram ID, групповой chat и неправильный
  membership revision fail closed; закрытый профиль владельца сохраняет работу.
- В unit/integration/acceptance тестах нет реальных паролей или cookies. В логах,
  таблицах, Telegram diagnostics и Mini App responses отсутствуют значения
  password, OTP, cookie, DOM и снимки HH.
- Реальный вход проверяется добровольной ручной приёмкой на отдельном аккаунте
  без отправки работодателю. Реальная отправка отклика остаётся отдельной
  приёмкой по существующему confirmation flow.
