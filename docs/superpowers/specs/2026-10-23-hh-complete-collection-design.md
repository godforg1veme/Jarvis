# Полный сбор HH для всех пользователей

Согласовано владельцем: дневные окна МСК, возобновление без дублей, независимые
запросы, уведомление о незавершённом сборе, CAPTCHA без обязательного login,
совместный выпуск и догон Сени. Последнее поручение явно разрешает публикацию
и обновление VPS. Права jobs проверяются одинаково для owner/admin/member;
блокировка/отзыв доступа и личные browser profiles сохраняются.

## Доказательства

Первый активный запрос Сени: 8953 результата за сохранённый период, 20 карточек,
ссылки pager заканчиваются page=99. Старый parser требует ссылку на вычисленную
последнюю страницу и возвращает saturation до чтения карточек. Один ошибочный
запрос блокирует ещё три. Ранее доставлены 71 карточка; их пересылать нельзя.

Read-only anonymous Chromium на DE: ISO date_from/date_to проигнорированы;
DD.MM.YYYY применяются. 20 октября — 677, 21 октября — 1437; обе даты вместе —
2114. Даты прочитанных вакансий соответствуют дням МСК; будущий день пуст.
API из обоих VPS возвращает 403, поэтому новый канал не подключаем.

## Решение и инварианты

- Browser передаёт календарные date_from/date_to DD.MM.YYYY вместо search_period.
  Старые CAPTCHA targets c search_period остаются допустимыми до разрешения.
- Reader проверяет запрошенную страницу и canonical next link. Усечённый pager
  не требует ссылки на дальнюю последнюю страницу. Метаданные found>2000 на
  первой странице доходят до collector, который делит окно ДО чтения вакансий.
- Дневная гранулярность обозначена явно в capabilities. Разбиение проходит по
  полуночи МСК: старое окно до midnight-1ms, новое от midnight. Если один день
  насыщен, его нельзя объявлять завершённым. Прогресс сохраняется, остальные
  окна получают свою попытку, пользователю идёт одно закрытое уведомление.
- Бюджет одной порции и быстрое продолжение не дают одному пользователю
  монополизировать collector. Изменение настроек/пауза/отзыв прекращают работу
  через текущие lease/revision guards. Rate-limit/CAPTCHA не обходятся.
- Общий checkpoint меняется только после завершения всех окон. Восстановление
  использует исходные lower/until и offset. Отдельные ошибки не стирают остаток.
- Доставки используют прежний уникальный ключ user/vacancy. Sent/unknown не
  переотправляются; новые карточки проходят текущие фильтры. Обработка 404
  исчезнувшей вакансии не должна блокировать остальные карточки.
- CAPTCHA eligibility совпадает с публичным сбором: активный непустой поиск,
  разрешение jobs и текущий private Telegram scope; connection нужен для
  действий с личным резюме, а не для получения картинки CAPTCHA.
- Уведомление сообщает, что сбор не завершён и прогресс сохранён; использует
  существующий job:menu. Не содержит запросов, URL, персональных данных,
  исключений и внутренних кодов. Повторная доставка не дублируется.

## Проверка и выпуск

Browser fixtures с реальным Chromium, PostgreSQL acceptance для ролей/отзыва/
scope и дедупликации, полный server/browser suite и Telegram gate. Выпуск
объединяет готовый ремонт branded CAPTCHA; обновляет browser/server/collector,
не Desktop. Сохранённые данные и профиль не сбрасываются. После выпуска
проверить каждого активного пользователя и завершение догоняющего обхода Сени,
отдельно от факта доставки. Если внешний HH не даёт остаток, зафиксировать
точное ограничение, сохранить прогресс и не заявлять о полном догоне.
