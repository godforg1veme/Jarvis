# Восстановление HH CAPTCHA после неопределённого ответа

Реализовано и выпущено 24 октября в составе общего ремонта.
[Результат и границы подтверждённого](../../updates/2026-10-24-hh-complete-collection.md).

Решение согласовано владельцем 23 октября 2026 года («давай»).

## Доказательства и пределы вывода

Владелец получил unknown после ручного ответа 23 октября в 17:29 МСК.
Сохранён receipt с HTTP 302, затем browser unhealthy/restart; завершённой
проверки результата нет. Это не доказывает причину unhealthy.
Обновление картинки остаётся в очереди, повторяется PREPARATION_FAILED.

В отдельном Chromium на DE воспроизведён дефект точного исходного target:
HTTP 200, classifyPage=vacancy, один валидный JobPosting; branded описание
находится в HH static markup, textContent непустой, innerText пустой из-за
visibility:hidden. readVacancyPage бросает JOB_HH_DOM_CHANGED. Проверка без
личной сессии доказывает дефект parser, но не содержимое текущей личной вкладки.

## Решение

1. Читать видимое описание прежним способом. Для единственного описания внутри
   штатного HH branded static контейнера допустить ограниченное чтение текстовых
   узлов, исключая script/style/template/noscript. Произвольные скрытые блоки,
   неоднозначное, пустое и чрезмерное содержимое отклонять.
2. Сохранить exact target, HTTP 200, CAPTCHA/security detection и JSON-LD checks.
   После unknown/restart разрешено только чтение target: успех снимает паузу;
   неясность сохраняет паузу. Ответ и operation ID не повторять.
3. Разделить причины ошибок подготовки на закрытые коды загрузки, формы,
   картинки, использованного ключа и проверки target. Не выводить URL, DOM,
   исключения, ответы, cookies, ключи картинок или пользовательские идентификаторы.
4. Проверить реальным браузером hidden branded target, unknown/restart и
   отсутствие повторного POST, а также CAPTCHA, неверный target и невалидный DOM.

## Область и выпуск

CommonJS, без новых production dependencies. Кнопки Telegram, callback grammar,
scope/revision/expiry/deduplication, OCR budget и подтверждения сохраняются.
Локальная реализация и тесты разрешены. Push/deploy не поручены; после проверки
предложить выпуск browser/server. Desktop не меняется.
