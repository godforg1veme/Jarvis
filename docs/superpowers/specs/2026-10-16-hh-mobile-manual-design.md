# Ручная проверка HH с телефона через Tailscale

16 октября 2026. Согласованный пользовательский сценарий; документ подготовлен
для проверки перед планом реализации. Реализация и публикация ещё не выполнены.

## Договорённости

Владелец попросил проходить капчу HH с телефона через Tailscale, согласовал
noVNC и кнопку «Открыть HH» в Telegram. Отдельным уточнением отменил таймер:
адрес постоянный, начатая ручная проверка остаётся открытой до «Готово».
Ссылка сохраняется после подтверждения и используется при следующей капче.
Сбор возобновляется после фактической проверки доступа к HH.

На DE Tailscale установлен, backend Running, узел online. В той же учётной
записи зарегистрирован iOS peer; во время проверки он offline. Serve уже
настроен, Funnel выключен. Существующие маршруты Serve сохраняются.
Windows, GitHub и оба VPS перед работой на `f6078a6`; веток, stash, PR и
незавершённых изменений не обнаружено.

Рассмотрены noVNC в Safari и отдельное VNC-приложение. Выбран noVNC: для
управления достаточно браузера телефона. DevTools/CDP не является мобильным UI.

## Что видит владелец

При неподтверждённом автоматическом восстановлении Jarvis отправляет прежнее
owner-only уведомление о капче с URL-кнопкой «Открыть HH». Та же постоянная
кнопка доступна в owner/private-chat меню поиска работы при включённом доступе.
Нижняя клавиатура и действия с откликами сохраняются.

Владелец включает Tailscale, открывает ссылку в Safari и видит состояние HH.
Страница предлагает «Начать ручную проверку», затем показывает браузер и
кнопку «Готово». GET ссылки не запускает изменяющее действие: предпросмотр или
сканер Telegram не должен включать управление либо приостанавливать поиск.
При новой капче pending-состояние уже запрещает дальнейшие обращения сборщика
к HH; явное начало передаёт управление владельцу.

Таймера нет. Закрытие вкладки телефона, потеря сети или перезапуск клиента
не подтверждают успех и не возобновляют сбор. Владелец возвращается по той же
ссылке. «Готово» временно блокирует ввод и выполняет GET исходного target.
Если страница действительно читается штатным reader, управление закрывается,
пауза снимается и активный поиск продолжает сохранённый прогресс. Если снова
капча, вход, отказ или неизвестная страница, ручная проверка остаётся открытой
с понятным объяснением. Ссылка никогда не становится bearer-секретом.

## Компоненты и передача управления

Включённый mobile-manual режим запускает один headed Chromium под виртуальным
X-дисплеем в прежнем job-browser контейнере. Это тот же persistent profile,
owner binding и primary resume. Второй Chromium с этим profile не запускается.
Без feature flag сохраняется текущий headless runtime.

В браузерный образ добавляются виртуальный дисплей, VNC server и noVNC.
Версии и источники фиксируются при подготовке сборки; runtime ничего не
скачивает. В контейнере нет shell/desktop launcher в пользовательском UI,
Docker socket, sudo, БД или model credentials. Chromium sandbox, SYS_CHROOT,
ограничения ресурсов, запрет downloads и service workers сохраняются.

Отдельный небольшой HTTP/WebSocket gateway-контейнер обслуживает только
manual UI, закрытые start/finish/status и VNC transport. У него нет HH profile,
БД, apply/read credentials или Docker socket. Gateway и browser соединены
отдельной приватной сетью; gateway не подключён к сетям bot server/collector.
Gateway публикуется только на loopback хоста для Tailscale Serve.

В browser отдельный manual broker получает ссылку на runtime. Он требует
отдельный manual credential для каждого control/transport запроса. Этот ключ
получают только gateway и browser; он не передаётся телефону, Telegram,
read/apply клиентам или модели. Raw VNC слушает только loopback внутри browser
контейнера. Только авторизованный broker может соединять его с transport.
Ни один компонент не управляет Docker и не перезапускает серверы. Прямые VNC
и CDP не публикуются ни в tailnet, ни в интернете.

Tailscale Serve проксирует отдельный путь `/hh/` на этот gateway, не заменяя
остальную конфигурацию. Funnel не включается. HTML, JS, шрифты и noVNC assets
отдаются локально; внешних CDN и сторонних ресурсов UI нет.

## Владение и защита управления

Gateway принимает запросы только с ожидаемыми Host/Origin и идентичностью
заранее настроенного владельца из identity headers доверенного Serve.
Host bind loopback, изоляция сети gateway и deployment-проверка обязательны:
одних присланных заголовков или принадлежности к tailnet недостаточно.
Browser broker никогда не доверяет Tailscale headers без отдельного manual
credential gateway. При установке привязка identity
сопоставляется с настроенным Jarvis owner; значения не попадают в Git/логи.
Другой пользователь tailnet, member, отсутствующая identity или неверная
конфигурация получают отказ, включая WebSocket upgrade.

Ссылка содержит только постоянный адрес. Управление требует owner identity,
защищённой сессии и CSRF-проверки. Cookie Secure/HttpOnly/SameSite=Strict;
изменения только POST, закрытый JSON shape, ограниченный body. WebSocket
проверяет Origin, identity, сессию и активную фазу; транспорт ограничивает
размер сообщений и соединения. При завершении существующее VNC-соединение
отключается. Inactive-страница показывает статус без управления браузером.

VNC не даёт доступ к файловой системе хоста. Clipboard/file transfer,
загрузки, произвольные proxy targets, shell и удалённое управление Windows
не входят в функцию. Снимки экрана и ввод не сохраняются в истории, БД,
логах, модели или Telegram.

## Состояние и сетевые границы HH

Manual coordinator хранит закрытые owner-bound состояния idle, pending,
active и checking с revision и исходным recovery ID. Запись атомарная,
приватная, ограниченная по размеру; неизвестный результат сохраняется после
перезапуска. Pending/active после рестарта не превращаются в idle. Сам
recovery ID не заменяется ради новой попытки.

Coordinator сериализует переход с текущей browser operation: активный
подтверждённый отклик сначала завершает либо сохраняет неизвестный результат.
Во время pending/active/checking новые HH read/apply operations отвергаются
закрытым manual-active кодом. Фильтры, пользовательское включение/выключение,
checkpoint и progress не перезаписываются. Проверки наличия ручного режима
не обращаются к HH. Collector ожидает с коротким ограниченным интервалом,
чтобы после успешного finish продолжить без долгой штатной задержки.

При передаче в ручной режим сохраняется точный канонический target текущей
операции в приватном состоянии, а не только hash. Открывается та же HH-сессия
и target, на котором возникла проверка; открытие одной главной страницы
не считается восстановлением. Одновременный автоматический OCR отключён
для переданной ручной операции.

Ручной режим не снимает сетевые ограничения целиком. Допускаются native HH
captcha init/answer, привязанные к текущей форме, картинке, CSRF и target.
Один answer POST для конкретного challenge фиксируется до отправки;
неизвестный результат не повторяется автоматически или под новым ID.
Новая картинка должна быть подтверждена состоянием страницы и отдельным
явным действием владельца. Redirect/retry POST остаются запрещёнными.
Произвольные POST, отправка отклика, смена резюме, видимости и ответы на тесты
через manual-доступ не разрешаются. Истёкший вход требует отдельной настройки
входа владельца; UI сообщает об этом, не ослабляя captcha allowlist.

«Готово» не снимает запрет повторения неизвестного POST. Его единственное
действие на HH — read-only reconciliation. Только штатный успешный reader
разрешает resolved и продолжение. Если владелец сам выключил поиск, finish
не включает его обратно. Повторное «Готово» для той же revision идемпотентно;
старые команды и команды от другой сессии/owner не действуют.

## Telegram change notice и затронутые места

Путь: collector → scoped job attention outbox → delivery/Bot → owner private
chat → URL кнопка → Tailscale Serve → gateway → manual coordinator → HH reader.
URL-кнопка только навигационная; права проверяются заново на gateway. Нового
callback семейства или guided-input kind не требуется. Прежние confirmation
и apply credentials не используются для ручного управления.

Ожидаемые изменения: `job-browser/src/browserMain.js`, `hhBrowser.js`,
`captchaRecovery.js`, отдельные coordinator/state/gateway модули и локальные
UI assets в отдельном gateway-пакете; Dockerfile и Compose opt-in настройки;
закреплённый WebSocket transport как часть noVNC integration; collector/client closed
codes; job Telegram delivery/menu URL button и конфигурация. Контракт меню
обновляется вместе с реализацией, а не объявляет невыпущенный UI установленным.
Общие правила остаются в AGENTS, runtime — в runtime-context/deploy,
фактические результаты — в отдельной release-записи.

## Приёмка

- Владелец/private chat видит постоянную кнопку; member/чужой chat — нет.
  Проверяются настоящие menu/delivery handlers, повторы и закрытый вывод.
- GET не меняет состояние; неверные identity, Host, Origin, CSRF, cookie,
  extra keys и WebSocket upgrade отвергаются до доступа к экрану.
- Одна HH-сессия: collector не обращается к HH и не отправляет OCR/answer,
  пока управление ручное. Проверяются concurrent start/finish и рестарт.
- Отсутствие таймера доказывается переходами с продвинутыми часами. Закрытие
  Safari не возобновляет поиск, повторное подключение работает по прежней ссылке.
- Реальный Chromium/X-дисплей/noVNC проверяются в изолированном Linux образе:
  отображение, ввод, native captcha, failed finish и successful reader finish.
- Подмена target/key/state/CSRF, повтор challenge, 307/308, попытка apply и
  смены видимости блокируются. Прежние application и CAPTCHA acceptance проходят.
- До выпуска: полный server test, Compose/preflight, source/runtime сверка;
  Serve/ACL проверка без изменения других путей и без публичных listeners.
- На телефоне: Tailscale online, Safari показывает HH, ввод работает, «Готово»
  проверяет target, сбор продолжает progress. Отдельно проверяется отказ
  другому tailnet identity. Это реальные проверки, а не вывод из fixtures.

## Выпуск

Публикация этой новой функции отдельно согласуется после реализации и тестов.
Обновляются server/collector и browser на DE, добавляется изолированный gateway,
обновляются исходники обоих VPS, точечно
Serve path и приватные настройки. Windows EXE и VPN runtime не меняются.
Существующие профили, секреты, mounts, backup policy и прочие Serve paths
сохраняются. Неподтверждённый результат установки проверяется по его маркеру,
без слепого повторного запуска.
