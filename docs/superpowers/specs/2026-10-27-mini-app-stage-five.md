# Mini App: оставшаяся часть этапа 5

Поручение: завершить согласованные личные операции, проверить настоящий E2E и
выпустить результат. Предыдущая часть этапа — память с migration051.
Живая приёмка Telegram остаётся этапом 6.

## Контракт операций

Все записи требуют preview и явного подтверждения в исходной Mini App. Клиент
сохраняет только UUID до POST; недоступное хранилище запрещает отправку. При
потере ответа GET читает тот же UUID. Отмена неизвестного UUID записывает
tombstone, поэтому запоздавший POST не выполнит действие. Новый UUID не служит
способом повторить неопределённую операцию.

`/mini/api/sections/:section/actions` объявляет доступные kinds и личные цели;
`/actions/:kind/:targetId` возвращает текущую цель и revision. POST
`/operations` принимает закрытый envelope `operationId/kind/targetId/revision/input`;
GET `/operations/:operationId` читает квитанцию, POST `/cancel` отменяет исходный
UUID. Квитанция migration052 и изменение записываются одной транзакцией.
Владелец, текущие права, живая сессия, section, kind, revision и SHA256
канонического запроса проверяются на сервере. Чужие UUID не раскрываются.

Лимит новых личных квитанций: 1000 за 24 часа и 20000 всего на пользователя.
Старые квитанции сохраняются для безопасного восстановления. Списки выбора
действий ограничены 30 целями; обычные списки разделов имеют отдельную пагинацию.

## Документы

UI принимает PDF, TXT и DOCX. Binary POST
`/sections/documents/uploads/:operationId` передаёт файл без base64. Origin,
CSRF, сессия и право проверяются до буферизации; лимит — меньшее из настройки
сервиса и 20 MiB, одновременно максимум четыре загрузки и две на пользователя.
Parser изолирован в child Fastify scope и не меняет бинарные маршруты других
подсистем. Файл готовится вне блокировки доступа, затем права проверяются снова.

Временный `wx`-файл продвигается через hard link без перезаписи. БД, ingestion
job и receipt атомарны. Rollback удаляет подготовленный файл; потеря COMMIT ACK
сохраняет файл до выяснения исходного UUID. Удаление проверяет владельца и
revision, удаляет документ с существующими каскадами и очищает файл после
подтверждённого commit. Квитанция не содержит текста, имени или storage key.

## Устройства и Life OS

Устройства: `pair`, `pair.cancel`, `revoke`; команд компьютеру этот API не
добавляет. Код живёт 10 минут, допускается до десяти активных кодов. Receipt
содержит AES-GCM ciphertext с ключом, производным от исходного session token
с отдельным назначением. Текст кода доступен только исходной живой сессии,
пока код не использован и не истёк. При новом входе можно отменить старый код.

Life: `reminder.create/reschedule/cancel`, `commitment.complete/dismiss`,
`project.pin/hide/restore`. Время формы — МСК, хранение — UTC. Скрытие проекта
предлагает точное время через 24 часа и допускает раннее восстановление.
Напоминание имеет origin `life_os`; адресат определяется сервером по своей
подтверждённой личной Telegram conversation. Если её нет, UI предлагает открыть
бота. Изменение домена, Life event и receipt используют одну транзакцию.

## Неизвестный результат HH

GET `/jobs/resumes/operations/:requestId/inspection` сверяет исходный UUID
чтением HH. При изменении роли unknown не становится failed автоматически;
зависший working старше 120 секунд также остаётся требующим сверки. Сервер
проверяет текущие jobs-права, connection/manager CAS и точное совпадение резюме.

POST того же `/confirm-inspection` требует `confirmed: true` и актуальную
`confirmationRevision`. Новый preview показывает исходные резюме и auto-raise.
Явное подтверждение завершает исходную операцию локально без повторного select
или raise. Устаревшая сверка, чужая операция, несовпадение HH и отзыв права
оставляют запись заблокированной. Повтор подтверждения завершённого UUID
возвращает сохранённый результат. Unknown raise блокирует включение auto-raise.

## Проверки

885 server tests; 32 последовательных PostgreSQL acceptance tests с полным
pipeline из 54 migration files; десять браузерных fixture-программ. Отдельный
`scripts/testMiniAppPersonalE2e.cjs` соединяет браузер, собранный UI, настоящий
Fastify, изолированную локальную PostgreSQL БД и временное файловое хранилище.
Он проверяет документы, устройства, Life и HH со сменой роли и потерей ответа.
Telegram SDK и внешний HH transport тестовые; реальные API не подменяются.
Новые DB/E2E fixtures требуют loopback URL без connection overrides.

Промежуточная независимая security-ревизия выполнена; заключительная повторная
ревизия HH недоступна из-за лимита помощников. Итоговый код проверен основным
агентом и перечисленными тестами. Физический Telegram/WebView не проверен.
