# Проверка native XHR капчи HH

16 октября 2026. Узкий ремонт ранее согласованной CAPTCHA recovery.
Реальный запрос исследован без отправки ответа. 16 октября владелец принял
новый формат и поручил выпуск. Browser установлен на DE из `e061386`;
live результат фиксируется в [записи выпуска](../../updates/2026-10-16-hh-native-captcha-request.md).

Подходы: оставить body-only проверку (HH остаётся заблокированным), разрешить
произвольный POST (теряются границы) или добавить точный native XHR контракт.
Выбран последний вариант. Старый закрытый body-контракт сохраняется.

Новый формат: только POST `https://hh.ru/account/captcha`, main frame,
resourceType `xhr`, без navigation, с пустым телом и urlencoded content type.
Query содержит ровно пять уникальных полей. `captchaText` равен проверенному
результату OCR, `captchaKey` — ключу выбранного изображения, `captchaState` —
state исходного action. `backurl` разрешается ровно в исходный target;
`failurl` — ровно в исходный form action. `x-xsrftoken` равен исходному `_xsrf`.
Чужой origin, credentials, fragment, лишние/повторные поля запрещены.

Источник изображения проверяется до OCR и повторно после него. Ключ ограничен
1024 символами без пробельных/control символов. URL запроса ограничен 24576
символами; он не попадает в диагностику, поскольку содержит ответ и state.

Журнал сохраняет attempted до разрешения POST. Разрешается одна отправка,
без redirect/retry; результат подтверждает только GET исходной вакансии.
Неопределённое состояние после перезапуска остаётся запрещённым для повтора.
Owner scope, apply credential, Telegram-подтверждение отклика не меняются.
Production-зависимости и OCR thresholds не меняются.

Проверки: подмена каждого поля/CSRF/ключа, duplicate/extra query, другой origin,
body, transport и navigation. Chromium проверяет оба формата, одну отправку,
перезапуск, чужого владельца и отказ. Изолированный HTTPS проверяет реальные
cookies и запрет POST redirect. Live HH проверяется отдельно после выпуска.
