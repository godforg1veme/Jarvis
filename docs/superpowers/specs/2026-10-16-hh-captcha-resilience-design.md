# Надёжная проверка HH и доставка CAPTCHA

Согласовано владельцем 16 октября 2026: исправить восстановление браузера,
очередь, истечение картинки, неопределённую доставку и добавить понятные сообщения
о затянувшейся проверке. Реализация локальная; публикация требует отдельного поручения.

## Подтверждённое состояние

На DE контейнер Chromium ограничен 1 GiB. `memory.events` содержит `oom_kill=1`,
Docker сообщает `OOMKilled=true`, но health HTTP возвращает успех. Coordinator
остаётся pending, revision растёт при повторных неудачных открытиях; новых photo
outbox записей после успешной предыдущей CAPTCHA нет. Точный внутренний exception
потерян, поэтому OOM подтверждён, а конкретный погибший Chromium subprocess не установлен.
Progress поиска сохранён, collector получает `JOB_HH_MANUAL_ACTIVE`.

## Решение

Вместо одного перезапуска или одного увеличения памяти восстанавливаем весь путь.
Новых production-зависимостей нет. CommonJS и Node.js 22.12+ сохраняются.

1. Browser открывает проверку в новой вкладке, закрывая предыдущую. Crash и потеря
   context не позволяют считать кэш картинки пригодным. Здоровье проверяется
   выполнением локального JS в Chromium с ограниченным временем, без запросов HH.
   Потеря context или зависание браузера завершает runtime с ошибкой: Docker
   восстанавливает процесс из прежнего profile/journal. При штатном close рестарта нет.
2. Запрос обновления имеет durable request UUID. Worker читает его без удаления,
   подтверждает только после сохранения результата и только для прочитанного UUID.
   Новый запрос, поступивший во время выполнения, не теряется. При временной ошибке
   запрос остаётся, повторы используют растущую задержку до 120 секунд.
3. Фото сохраняет lease, attempts и время следующей попытки. Только явно отвергнутый
   Telegram 429 допускает ограниченный повтор той же записи с retry_after. Потеря ACK,
   зависшая sending lease и неизвестный ответ HH блокируют автоматическую замену;
   явное «Обновить картинку» снимает блок только для новой картинки, не повторяет POST.
4. Просроченная, использованная или потерянная при crash картинка возвращает закрытый
   результат refresh_required. Worker отправляет одно durable уведомление с прежней
   кнопкой обновления. Idle означает отсутствие активной CAPTCHA: явный запрос
   получает сообщение об этом, без утверждения о проверенном доступе к HH.
5. Повторные сбои подготовки, failed/unknown delivery и необходимость новой картинки
   дают безопасные фиксированные уведомления через существующий delivery outbox.
   Scope привязан к owner/private conversation/chat и перепроверяется перед доставкой.
   Outbox уведомлений не содержит ответ, PNG, HH URL, исключения или credentials.

## Неизменные границы

Кнопки, callback grammar, scopes, срок картинки 10 минут, запрет AI/history для
ответа и native POST после durable consumption сохраняются. Старая картинка после
явного refresh не принимается. Восстановление не повторяет answer/apply POST и
не сбрасывает profile, progress, фильтры, journal или claims. Поиск, выключенный
владельцем, сам не включается. Ресурсный лимит не увеличиваем без измерения бюджета.

## Проверки и приёмка

Unit/HTTP: crash, закрытый context, зависший JS, отказ health, recovery вкладки,
тайм-аут, backoff и single-flight, потеря refresh и конкурентный refresh, 429/failed/
unknown send, истечение lease и изображения, used/unknown answer, безопасные notices.
Настоящий PostgreSQL и message/menu handlers: owner/foreign scope, одна consumption,
сохранение request UUID и dedup notices. Linux Chromium/HTTPS: падение renderer,
новая вкладка, restart, неизменные claims и отсутствие повторных POST.
Обязательный Telegram gate, полный server suite, browser suite, Compose policy.

После отдельного поручения на выпуск: GitHub main и оба VPS source, DE server/browser,
migration и health. Проверить доставку настоящего фото; ответ вводит владелец.
Desktop не меняется.
