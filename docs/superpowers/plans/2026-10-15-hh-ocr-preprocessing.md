# HH OCR Preprocessing Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task.

**Goal:** Проверить и реализовать ограниченное улучшение подготовки картинок при текущей модели.

**Architecture:** Изолированный offline опыт → небольшой модуль подготовки → строгий выбор результата в прежнем worker. Живая HH-сессия не нужна для повторной обработки сохранённых PNG.

**Tech Stack:** Python, Pillow, numpy, ONNX Runtime; текущие pinned зависимости.

**Spec:** [Согласованный подход](../specs/2026-10-15-hh-ocr-preprocessing-design.md).

## Global Constraints

Без новых зависимостей, весов, внешних API, production release и POST ответов HH.
Сохранить владельца, журнал и image/CPU/RAM/deadline bounds. Не раскрывать OCR-текст.

### Task 1: Offline проверка гипотез

- [x] Получить только закрытые характеристики сохранённых PNG и baseline.
- [x] Сравнить оригинал, контраст, инверсию, ограниченные альтернативы геометрии.
- [x] Разделить согласие кандидатов и проверенную точность; записать ограничения.

### Task 2: Ограниченное улучшение worker

**Files:** `job-ocr/worker.py`, при необходимости `job-ocr/preprocessing.py`, `job-ocr/test_worker.py`, `job-ocr/Dockerfile`.

- [x] По результатам опыта выбрать минимальный оправданный набор изменений.
- [x] Проверить полезное распознавание и отказ на пустом/случайном входе, конфликт и низкую уверенность.
- [x] Проверить существующие input bounds и CPU/deadline в изолированном образе.
- [x] Если устойчивого улучшения нет, сохранить отрицательный результат без ослабления gate. Сохранён отказ на неоднозначном задании, не выбран перенос на оригинальный PNG.
