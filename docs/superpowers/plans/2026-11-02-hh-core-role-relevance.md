# HH: основные обязанности вместо совпадения слов

Поручение владельца: закрыть пункт 1 предыдущего списка оптимизаций.
Цель: отклик допускается по основной работе в выбранном направлении;
упоминания AI-инструментов и переносимого клиентского опыта недостаточно.

## Решение

Одна оценка той же GLM 5.3 Flash со строгим JSON и прежним лимитом 6000.
Новые обязательные данные решения: основная профессия, точный целевой запрос
из настроек, отношение `core/tool_only/adjacent/unclear`, до трёх цитат обязанностей.
При `core` код проверяет принадлежность запроса и наличие цитат в полном описании.
Для надёжного выбора код даёт до 96 исходных фрагментов по 10–240 символов.
Полный короткий список ограничивает цитаты enum; длинный список равномерно
выбирается по всему описанию и допускает другие точные цитаты полного текста.
Запросы ограничены настройками текущего пользователя.
Список фрагментов не является семантическим фильтром, полное описание сохраняется.
`tool_only/adjacent` означают известный skip OUT_OF_DIRECTION. Неясность либо
неподтверждённое `core` означают skip UNCERTAIN, без создания письма и общей паузы.
Формально неверный JSON по-прежнему является ошибкой модели, без повторного вызова.

Смысл обязанностей определяет LLM; код проверяет доказательства и закрытую форму.
Запрета профессий или отраслей по названиям нет. Внедрение AI в продажи/поддержку,
создание RAG/агентов, AI no-code, обучение и QA могут подходить по основной работе.
Навыки резюме оцениваются после подтверждения направления и не меняют личную цель.
Worker повторяет проверку перед письмом и сохраняет оценку с selectionPolicyVersion=2.
