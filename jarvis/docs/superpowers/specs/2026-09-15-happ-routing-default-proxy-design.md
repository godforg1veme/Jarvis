# Happ routing: proxy by default with Russian direct exceptions

## Goal

Make the existing Happ routing profile route all traffic through the active VPN
by default while preserving direct access to Russian services and domestic IP
ranges. This removes the current failure mode where unlisted destinations,
including apps that connect by IP address, bypass the VPN.

## Scope

- Change `GlobalProxy` generated by `server/src/vpn/vpnRoutingService.js` from
  `"false"` to `"true"`.
- Preserve the existing explicit direct rules for Russian domains and
  `geoip:ru`, as well as the existing DNS settings and explicit proxy rules.
- Update the affected unit test and user-facing documentation so they describe
  routing through the active Happ VPN profile rather than Hysteria2 alone.

## Behaviour

Happ evaluates explicit routing rules before its default outbound. With global
proxy enabled, the existing Russian direct rules continue to use the physical
network, while every unmatched destination uses the currently selected Happ
VPN profile. This applies equally to Hysteria2 and VLESS imports.

## Verification and rollout

Run the routing and VPN command unit tests, then the server test suite. Deploy
only the server after the commit is pushed. Confirm the public health endpoint
and the routing landing page. On iPhone, re-import the updated routing profile,
reconnect, then manually verify a foreign IP-check service, Telegram, and a
Russian direct service. Switching the active VPN protocol to VLESS is a
separate, manual acceptance step after this rollout.
