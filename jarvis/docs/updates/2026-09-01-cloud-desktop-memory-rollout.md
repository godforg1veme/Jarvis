# Итог развёртывания Cloud Desktop и памяти

Статус на 2026-09-01. Этот документ фиксирует проверенное текущее состояние и
заменяет противоречивые устные заметки; исторические спецификации и планы в
`docs/superpowers/` остаются историей решений.

## Что работает

- VPS на Ubuntu 24.04 запускает Fastify control plane и приватный
  PostgreSQL/pgvector в Docker Compose. Публичный путь
  `jarvis.rilora.ru → Cloudflare Tunnel → server:3210` проверен через
  `/health/ready`.
- Telegram — первый облачный клиент: allowlist, дедупликация обновлений,
  изолированные пользовательские переписки, личность Jarvis и
  OpenAI-совместимый шлюз модели.
- Windows Jarvis Desktop собран в NSIS-установщик. Он подключается к серверу
  одноразовым кодом из Telegram, хранит токен устройства локально через DPAPI
  и открывает исходящую защищённую WSS-сессию. Один пользователь может иметь
  несколько устройств.
- Desktop поддерживает чат, TTS и постоянный локальный wake word «Джарвис».
  Для wake word используется лёгкий Vosk runtime на ПК; Large Whisper, Python,
  CUDA и локальная большая ASR-модель пользователю не требуются.
- Долговременная память MVP общая для Telegram и всех привязанных Desktop:
  «запомни», «забудь», «исправь», «что ты обо мне помнишь». Простые факты могут
  извлекаться автоматически; пароли, токены и платёжные данные не сохраняются.
- Состояние устройств строго ограничено владельцем. `/devices` и вопрос
  «К какому ПК я привязан?» отвечаются сервером напрямую, поэтому модель не
  может выдумать отсутствие уже привязанного ПК.

## Защита и устойчивость

- В prompt попадают только данные текущего пользователя. Имена устройств
  передаются как данные, не как инструкции; токены, внутренние ID и
  capabilities модели не показываются.
- Ответы, в которых модель называет себя Gemini, DeepSeek, ChatGPT и т. п.,
  отклоняются даже при Markdown-оформлении. Сохранённые подобные ответы не
  подаются обратно в модель как история.
- Fallback-код не повторяет запрос другой модели, если тот мог бы выполнить
  инструменты. На текущем VPS резервная модель ещё не настроена: таймаут
  основного провайдера вернёт пользовательскую ошибку, пока не будет выбран
  отдельный провайдер/модель.
- Cloudflare token хранится только в ignored `deploy/secrets/` на VPS с правами
  `0600`. Контейнер ingress запускается от root только для чтения этого
  read-only mount; это не даёт доступ модели или приложению к секрету.

## Что пока не следует считать готовым

- Персональная база знаний с загрузкой TXT/Markdown/PDF/DOCX, embeddings и
  цитатами по страницам.
- Регулярные резервные копии, шифрование, off-VPS хранение и тестовое
  восстановление.
- Серверная ASR: HTTP-контракт есть, но конкретный Qwen3-ASR/Faster Whisper
  провайдер выключен до бенчмарка на DE-4.
- Исполнение удалённых команд на Windows. Привязка, presence и контракты есть,
  но диспетчеризация и подтверждение изменяющих действий ещё не реализованы.
- PWA, WireGuard, изображения/камера и потоковое видео.

## Ближайший порядок работы

1. Выбрать и настроить резервную модель для безопасных текстовых запросов.
2. Реализовать личную базу знаний и удаление документов вместе с фрагментами.
3. До накопления ценной памяти внедрить резервные копии и тест восстановления.
4. После появления DE-4 измерить Qwen3-ASR и Faster Whisper на русском, затем
   включить выбранный серверный ASR-провайдер.
