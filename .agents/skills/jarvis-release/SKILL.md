# Выпуск Jarvis

Найди Git root текущей задачи; canonical Windows checkout: `F:\test\jarvis`.
Прочитай его `AGENTS.md` и `docs/release-workflow.md`. Их проверенные правила
важнее скопированных в skill дат и SHA. Если репозиторий недоступен, не угадывай
состояние VPS. Отслеживаемая версия skill находится в `.agents/skills/jarvis-release/`.

Перед работой и перед публикацией:

```powershell
py deploy/scripts/release-status.py --fetch
gh pr list --state open --json number,headRefName,baseRefName
```

Изучи все ветки с уникальными коммитами, пересечения файлов, активные worktrees
и PR. Сохраняй чужую активную/грязную работу. Учитывай нужные изменения с тестами;
не сливай непонятную ветку автоматически. Возраст ветки не разрешает её удаление.
Удаляй только завершённые ветки после проверки включения изменений и отсутствия
активного PR/worktree. Короткая task branch допустима после инвентаризации;
`main` остаётся единственной постоянной общей веткой.

В рамках порученной публикации: проверь diff/тесты/документы, получи свежую
`origin/main`, объедини проверенную работу, push без force. Затем обнови чистые
source checkouts обоих VPS через fast-forward и выполни source guard до staging.
Сохраняй dirty source; никогда не используй production reset/clean.

Сравни работающие компоненты с опубликованной версией. Обновляй только
отличающиеся компоненты по руководству: отдельный server release с записанным
SHA, Host Agent через полный staged tree, Desktop через сборку/установку при
порученном обновлении клиента. Одинаковая версия package или успешный pull
не доказывают одинаковый установленный код. MD-only изменения не требуют
рестарта. Секреты, bind mounts, пользовательские данные, VPN-ключи и токены
подписок сохраняются; неопределённая операция проверяется по исходному состоянию/ID.

Итоговая проверка на принятой чистой `main`:

```powershell
py deploy/scripts/release-status.py --fetch --vps --desktop-app "C:/Program Files/Jarvis Desktop/resources/app" --check
```

`py` на Windows, `python3` на Linux. При другом пути установки передай настоящий
`resources/app`. Скрипт проверяет состояние, ничего не развёртывает. Ненулевой
результат объясни и устрани в пределах поручения; не удаляй чужую ветку ради
успешной проверки. Свежесть VPN-проб, нажатия в Telegram и голос проверяются отдельно.

Для MD используй таблицу владельцев в руководстве: один основной источник
на тему, короткие ссылки в AGENTS/CLAUDE/gemini, датированные результаты отдельно.
Применяй Humanizer при доступности. Итог: что опубликовано, что работает на
DE/NL/Desktop, что проверено и что ещё осталось. Не заявляй о полном выпуске
при частично обновлённых узлах или неподтверждённом клиенте.
